API Reference

Pyxil framework component guide.

Welcome to Pyxil

This guide summarizes the namespaces and components defined in the Pyxil Software Requirements Specification, version 0.3.

Namespaces Overview

The SRS defines the following namespaces:

Namespace Purpose
Pyxil.Framework Core framework classes and game/window management.
Pyxil.Framework.Audio Core audio framework classes and audio playback.
Pyxil.Framework.Content Content loading and management through ContentManager.
Pyxil.Framework.Graphics Rendering, textures, and visual effects.
Pyxil.Framework.Input Input and I/O, including keyboard, mouse, and gamepad.
Pyxil.Framework.Utils Utilities that assist with game development.

Core Components

The SRS names GameManager, GameWindow, GameWindowManager, and GraphicsDeviceManager as framework components. GameWindow and GameWindowManager are required to support creating and managing multiple application windows.

Graphics

Pyxil.Framework.Graphics covers rendering, textures, and visual effects. GraphicsDeviceManager is one of the classes identified for managing graphics resources.

Input

InputManager is intended to manage input events. Pyxil.Framework.Input must cover keyboard, mouse, and gamepad input across supported desktop environments.

Content Manager

ContentManager, in Pyxil.Framework.Content, is responsible for loading and managing game content.

Audio

Pyxil.Framework.Audio contains the audio components. The SRS requires audio playback and audio-device support on supported desktop platforms.

Utilities

Pyxil.Framework.Utils is reserved for tools that assist game development. The SRS does not yet specify individual utility classes.

Logging and Errors

Pyxil must provide structured log entries with relevant event details, severity, timestamp, and source component. The SRS lists these severity levels: INFO, WARNING, ERROR, CRITICAL, DEBUG, and EVENT.

Error messages should identify the failed operation and, where practical, explain the cause or suggest a correction.

Resource Cleanup

The framework should attempt to release resources such as windows, audio, and memory when they are no longer in use, including when an exception interrupts execution.

Platform Support

The SRS targets Windows, Linux, and macOS desktop environments, including 64-bit systems. Supported Python versions should be published for each release. Packaging compatibility is to be validated for PyInstaller, py2exe, and Nuitka.

The SRS proposes a startup target of under five seconds for at least 94.4% of measured attempts; it notes that this target still requires stakeholder confirmation.

Getting Support

Report defects, ask questions, or suggest features through the Pyxil issue tracker. Include the Pyxil and Python versions, operating system, steps to reproduce, and relevant error output.

User Manual: Getting Started

  1. Choose a Pyxil release and check its published Python and platform support.
  2. Use GameManager to organize the game and window components.
  3. Use GameWindow and GameWindowManager when managing windows.
  4. Connect graphics, input, content, and audio through their respective managers and namespaces.
  5. Use structured logs and detailed error messages when troubleshooting.
  6. Ensure windows, audio, and other resources are released during shutdown and error handling.
  7. Validate packaged builds on every operating system and Python version you intend to support.
