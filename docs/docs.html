Pyxil framework component guide.

Welcome to Pyxil

This guide introduces the main areas of a desktop game framework: the game loop, timing, graphics, input, and resource management.

These are conceptual component areas. Pyxil's Python implementation and public API are not included in this repository yet, so class names and code examples are not documented here.

Component Overview

Pyxil is organized around these core responsibilities:

Component Area Purpose
Pyxil.Core Owns the game lifecycle and the repeated update-and-draw cycle.
Pyxil.Graphics Coordinates drawing and the visual output of a game.
Pyxil.Input Provides a place to collect and respond to player input.
Pyxil.Resources Organizes the loading and lifetime of resources used by a game.

Game Lifecycle

A game lifecycle coordinates startup, repeated updates, drawing, and shutdown. Keep game state changes in the update step and visual work in the draw step.

Frame Time

Frame time is the elapsed time between updates. Use elapsed time when calculating movement or animation so gameplay is less dependent on the machine's frame rate.

Graphics

The graphics area is responsible for presenting the game's visual state. Keep rendering separate from input handling and game-state updates.

Input

The input area represents player actions. Read input during the update cycle and use it to change game state rather than drawing directly from input handlers.

Resources

The resources area provides a place to organize assets used by the game. Centralizing resource ownership helps avoid loading the same asset repeatedly and makes cleanup easier.

Getting Started

  1. Plan the game state and the changes that happen during each update.
  2. Separate state updates from rendering.
  3. Use elapsed frame time for time-based movement and animation.
  4. Keep input and resource handling separate from game rules.
